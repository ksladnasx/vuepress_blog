## 1. 高频必背

### JavaScript

#### 事件循环

执行顺序：

1. 同步代码。
2. 清空当前微任务队列。
3. 执行一个宏任务。
4. 再清空微任务，循环往复。

常见宏任务：`setTimeout`、`setInterval`、I/O、用户事件。 
常见微任务：`Promise.then/catch/finally`、`queueMicrotask`、浏览器中的 `MutationObserver`。

注意：

- `async/await` 本质上基于 Promise，`await` 后面的代码通常进入微任务。
- `setTimeout(fn, 0)` 不是立即执行，只是进入宏任务队列。
- `process.nextTick` 是 Node.js 特殊微任务，面试时说明运行环境。

#### this、箭头函数、闭包

- 普通函数的 `this` 由调用方式决定：对象调用、普通调用、`new`、`call/apply/bind`。
- 箭头函数没有自己的 `this`，继承定义时外层作用域的 `this`，不能作为构造函数。
- 闭包：函数引用了外层作用域变量，即使外层函数执行结束，变量仍可能被保留。
- 闭包场景：防抖、节流、定时器、缓存、私有变量、历史状态。

#### 原型链与 `new`

- `prototype`：构造函数的显式原型。
- `__proto__`：对象指向其原型的隐式链接。
- 属性查找：对象自身 -> 原型链 -> `Object.prototype` -> `null`。
- `new`：创建对象 -> 连接原型 -> 绑定 `this` -> 执行构造函数 -> 返回对象；构造函数显式返回对象时优先返回该对象。

#### 数组和深拷贝

会修改原数组：`push`、`pop`、`shift`、`unshift`、`splice`、`sort`、`reverse`。  
通常不修改原数组：`slice`、`concat`、`map`、`filter`、`forEach`、`find`、`some`、`every`。

- `slice`：截取并返回新数组，不改变原数组。
- `splice`：删除、替换或插入，改变原数组。
- 去重：`[...new Set(arr)]`；对象数组需按业务字段用 `Map` 或对象索引。
- `JSON.stringify/parse` 深拷贝限制：丢失 `undefined`、函数、Symbol、循环引用、特殊对象类型，`Date` 也会变成字符串。
- 面试更稳的回答：根据数据类型选择递归拷贝，使用 `WeakMap` 记录已访问对象，处理循环引用。

#### 防抖和节流

- 防抖：连续触发时不断重置计时器，只在停止触发后执行一次。适合搜索输入、窗口调整后的计算。
- 节流：一段时间内最多执行一次。适合滚动监听、拖拽、上传进度更新。
- 上传进度一般使用节流，避免高频进度事件导致重复渲染；展示层可控制在约 50-100ms 更新一次。

#### Promise

- `Promise.all`：全部成功才成功，一个失败即失败，适合强依赖的并行任务。
- `Promise.allSettled`：等待全部结束，分别拿到成功/失败结果，适合批量任务。
- `Promise.race`：第一个 settled 的 Promise 决定结果，适合超时控制。
- `Promise.any`：第一个 fulfilled 的 Promise 决定结果，全部失败才失败。
- 异步 `filter`：先 `Promise.all` 执行异步判断，再用结果筛选，不能直接把 `async` 回调传给普通 `filter`。

### Vue 3

#### Vue 2 与 Vue 3

| 维度 | Vue 2 | Vue 3 |
|---|---|---|
| 响应式 | `Object.defineProperty` | `Proxy` |
| 数组/新增属性 | 存在监听限制，需要特殊 API | 代理整个对象，覆盖更完整 |
| 组织方式 | Options API 为主 | Composition API 更适合逻辑复用 |
| 性能 | 组件粒度更新 | 编译优化、静态提升、区块树、更新更精细 |
| TypeScript | 支持成本较高 | 类型推导和组合式写法更友好 |

`Proxy` 的核心优势：可拦截属性读取、写入、删除、遍历等操作，可以直接感知新增属性和数组索引变化。





#### `ref`、`reactive`、`nextTick`

- `ref`：适合基本类型，也可包裹对象；脚本中通过 `.value` 访问。
- `reactive`：返回对象代理，适合对象和数组；不能直接替换整个代理引用。
- `.value` 的原因：基本类型没有可被代理的属性，需要通过容器对象统一拦截读写。
- `nextTick`：等待 Vue 完成当前批次 DOM 更新后执行。适合更新数据后读取 DOM 尺寸、聚焦输入框。

#### 生命周期

常用顺序：

`setup` -> `onBeforeMount` -> `onMounted` -> `onBeforeUpdate` -> `onUpdated` -> `onBeforeUnmount` -> `onUnmounted`

- `onMounted`：DOM 已生成，适合初始化第三方组件、读取 DOM。
- `onUpdated`：DOM 更新后触发，谨慎修改响应式数据，避免循环更新。
- `onUnmounted`：清理定时器、事件监听、SSE/WebSocket、Observer。

#### 组件通信与状态管理

- 父传子：`props`。
- 子传父：`emit`。
- 跨层级：`provide/inject`。
- 全局共享：Pinia；Vue 2 常见 Vuex。
- 兄弟组件：提升状态到共同父组件，或使用 Pinia。
- 组件库事件总线只适合少量、明确的跨组件通知，不要替代正常状态管理。

#### `key`、`v-if`、`v-show`、缓存

- `key` 用于标识节点身份，帮助 Diff 正确复用和移动节点。
- 不建议用 `index` 作 `key`：列表插入、删除、排序后，节点身份会错位。
- `v-if`：真正创建/销毁，适合低频切换。
- `v-show`：通过 `display` 切换，适合高频切换。
- `keep-alive`：缓存组件实例，减少重复创建和销毁；注意缓存状态可能不是最新，需要配合 `activated/deactivated`。

#### 路由

- Hash：地址带 `#`，刷新通常不需要服务端额外配置。
- History：地址更自然，但刷新非根路径时服务端需回退到 `index.html`。
- 动态权限路由：登录后获取权限 -> 过滤路由 -> `router.addRoute` -> 处理首次跳转 -> 退出时清理状态和路由。

### CSS、布局与适配

- 两栏布局：优先使用 Flex 或 Grid；固定侧栏 + `flex: 1` 主内容。
- `flex: 1` 通常等价于 `flex: 1 1 0%`，表示允许放大和缩小，并按剩余空间分配。
- `flex: 1` 失效常见原因：父元素没有可分配空间、子元素 `min-width: auto` 导致无法收缩、固定宽度或内容溢出。
- BFC：独立的块级格式化上下文。常见作用：清除浮动、阻止外边距折叠、隔离布局。
- `margin-top` 外边距折叠：相邻块级元素或父子块级元素可能发生折叠，BFC、边框、内边距或 `flow-root` 可隔离。
- 行内元素间空格来自 HTML 源码中的空白字符；需要无空格排版、调整字体或使用 Flex 解决。
- 响应式：`flex/grid` 负责布局，媒体查询负责断点，`rem/vw` 负责尺寸，`max-width/min-width` 负责边界。
- 大屏看板：可用固定设计稿尺寸 + `transform: scale`；下拉框等弹层要处理挂载容器和坐标系偏移。

### HTTP、浏览器与网络

#### HTTP 状态码

- `2xx`：成功。
- `3xx`：重定向或缓存相关。
- `4xx`：客户端请求错误。
- `5xx`：服务端错误。
- `301`：永久重定向，浏览器和搜索引擎通常会长期缓存。
- `302`：临时重定向，语义上不代表资源永久迁移。
- `304`：资源未修改，客户端可继续使用缓存，不返回资源正文。

#### 缓存

- 强缓存：命中后不请求服务器，主要看 `Cache-Control`、`Expires`。
- 协商缓存：仍向服务器发请求，通过 `ETag/If-None-Match` 或 `Last-Modified/If-Modified-Since` 判断是否返回 `304`。
- 构建产物常使用带 hash 的文件名，配合长期强缓存；HTML 通常设置较短缓存，避免入口文件更新不生效。

#### CORS 与安全

- 简单请求：满足方法、请求头、Content-Type 等限制，浏览器直接发请求，服务端返回允许跨域响应头。
- 复杂请求：先发 `OPTIONS` 预检，服务端通过后才发正式请求。
- XSS：攻击者注入脚本。防护：转义输出、避免直接使用 `innerHTML`、限制富文本、CSP。
- CSRF：借助用户已有身份发起伪造请求。防护：SameSite Cookie、CSRF Token、校验 Origin/Referer。

#### URL 到页面

DNS 解析 -> TCP 三次握手 -> TLS 握手（HTTPS）-> HTTP 请求 -> 解析 HTML/CSS/JS -> DOM/CSSOM -> 渲染树 -> Layout -> Paint -> Composite。

阻塞渲染常见来源：同步脚本、未优化的 CSS、首屏大图、字体阻塞、大量 DOM、复杂布局和长任务。

#### SSE、WebSocket、HTTP

- SSE：服务端单向推送，基于 HTTP，浏览器可自动重连，适合 AI 流式输出。
- WebSocket：双向实时通信，适合聊天室、协同编辑、实时控制。
- 普通 HTTP：请求和响应完成后结束，适合常规接口。
- SSE 断线处理：保存会话/消息 ID，使用 `AbortController` 关闭请求，重连时携带游标或重试参数，避免重复渲染。

### 性能优化

#### 指标

- LCP：最大内容绘制，反映主要内容何时出现。
- FCP：首次内容绘制。
- INP：用户交互响应延迟。
- CLS：布局稳定性。
- 面试中说清楚数据来源：本地 Performance/Lighthouse 用于定位，真实用户监控用于验证线上效果。
- 简历中的 LCP：从约 2.4s 优化到约 1.5s。回答时必须补充采样范围、网络条件、版本对比和是否为 P50/P75/P90，避免只报单次本地结果。

#### 优化路径

1. 先用 Lighthouse、Performance、Network、Bundle Analyzer 定位瓶颈。
2. 首屏减少请求和资源体积：压缩图片、懒加载非首屏资源、合理预加载关键资源。
3. 构建优化：路由懒加载、组件和第三方依赖拆包、避免把高频变化内容打进稳定公共包。
4. 渲染优化：减少大 DOM、拆分组件、虚拟列表、避免重复计算、对高频事件节流。
5. 运行时优化：Web Worker 处理重计算，避免主线程长任务。
6. 重新测量并对比真实数据，确认没有牺牲功能和稳定性。

Table 优化重点：服务端分页、列配置稳定、避免整表响应式深层更新、虚拟滚动、按需渲染、筛选输入防抖、拆分复杂单元格。

### 组件库与工程化

#### 什么时候封装组件

满足以下任一条件即可考虑：

- 多处复用且交互规则一致。
- 业务逻辑复杂，单页维护成本高。
- 需要统一样式、行为、校验和错误处理。
- 需要沉淀为团队公共能力。

封装前先明确：输入、输出、默认值、插槽、事件、受控/非受控模式、异常状态和可扩展点。

#### Table 设计

- 视图层：表格、空状态、加载态、分页、批量操作。
- 配置层：列定义、格式化函数、筛选项、权限标识。
- 状态层：分页、排序、筛选、选中行、请求状态。
- 事件层：查询、重置、刷新、选择变化、行操作。
- 大数据量场景：分页或虚拟列表，不要一次性渲染数万行。

受控组件：状态由父组件传入，组件通过事件通知修改。  
非受控组件：组件内部维护状态，只暴露必要方法。  
通用组件优先受控，业务内部简单组件可适当非受控。

#### 工程化

- Vite 开发快：开发阶段原生 ESM 按需加载，减少全量打包等待；生产环境仍会进行打包优化。
- Webpack Loader：转换单个模块类型，如 TS、CSS、图片。
- Webpack Plugin：参与构建生命周期，做压缩、生成文件、注入变量等全局处理。
- `npm` 是包管理工具；Node.js 是 JavaScript 运行时。
- `dependency`：运行时依赖；`devDependency`：开发和构建依赖；`peerDependency`：要求宿主项目提供的兼容依赖。
- npm 安装过程：读取 `package.json` 和 lock 文件 -> 解析依赖树 -> 从 registry 下载 -> 校验 -> 写入 `node_modules` -> 更新 lock 文件。

## 2. 项目题主线

### 文件分片上传

推荐按以下顺序回答：

1. 选择文件，读取大小、类型、名称。
2. 根据阈值判断是否分片；小文件直接上传，大文件按固定大小切片。
3. 每个分片带 `fileId/fileHash/chunkIndex/chunkHash` 等信息。
4. 并发上传，限制最大并发数，失败重试，支持暂停和取消。
5. 服务端校验分片，记录已上传分片，合并时按 `chunkIndex` 排序。
6. 合并后校验完整性，避免分片顺序错误或内容缺失。
7. 断点续传：客户端生成稳定文件标识，先询问服务端已上传分片，只补传缺失部分。

追问要点：

- 分片大小不是越大越好：太小会增加请求数，太大会降低失败重试效率；根据网络、服务端限制和文件大小压测决定。
- 并发数应可配置，通常从 3-6 起步，结合带宽、CPU、服务端限流调整。
- 进度：已完成分片字节数 / 文件总字节数；不要简单按分片数量计算，除非分片大小完全一致。
- MD5 可用于文件或分片完整性校验，但大文件计算应考虑 Web Worker，避免阻塞主线程。
- 半数分片失败时，保留成功结果，只重试失败分片；全部完成后再提交合并。
- 同一文件切片下标必须稳定：固定 `chunkSize`、按顺序计算 `start/end`、使用 `chunkIndex` 传输。

### AI 对话平台

- 平台定位不是简单复制 ChatGPT，而是围绕企业 Agent 的工作流编排、知识库、模型配置、会话和权限提供业务能力。
- 流式响应优先使用 `fetch + ReadableStream`，便于自定义请求头、POST body、取消、错误处理和中断恢复。
- `EventSource` 适合标准 GET SSE，使用简单，但对请求控制和自定义参数不如 fetch 灵活。
- 前端流程：发送消息 -> 创建会话/消息记录 -> 读取流 -> 增量拼接 -> 节流更新 UI -> Markdown 渲染 -> 结束后落库或刷新状态。
- 使用 `AbortController` 实现停止生成；组件卸载时必须关闭连接。
- 流式 Markdown 要避免每个 token 都触发完整复杂渲染，可按帧或时间窗口批量更新。
- 需要处理：网络断开、接口报错、空响应、重复消息、模型超时、用户重复点击、半截 Markdown。

### 权限系统

RBAC 至少拆成：

- 菜单权限：是否显示导航入口。
- 路由权限：是否允许进入页面。
- 按钮权限：是否显示新增、编辑、删除等操作。
- 数据权限：能看到哪些用户、资源和记录。

核心流程：登录获取 Token 和权限 -> 前端生成菜单/路由 -> 路由守卫校验 -> 组件按钮校验 -> 请求层携带身份 -> 后端最终校验。  
前端权限只负责体验，真正安全边界必须在后端。

## 4. 算法题速记

### 合并区间

> 给定若干区间 `[[1,3],[2,6],[8,10],[15,18]]`，合并所有重叠区间，返回不重叠的结果。

解题步骤：

1. 按每个区间的起点升序排序，示例排序后仍为 `[[1,3],[2,6],[8,10],[15,18]]`。
2. 先把第一个区间放入结果数组，记结果末尾区间为 `last`。
3. 依次取当前区间 `current`：
   - 如果 `current[0] <= last[1]`，说明有重叠，将 `last[1]` 更新为 `max(last[1], current[1])`。
   - 如果 `current[0] > last[1]`，说明没有重叠，直接把 `current` 加入结果数组。
4. 示例中 `[1,3]` 和 `[2,6]` 合并为 `[1,6]`，最终结果是 `[[1,6],[8,10],[15,18]]`。

复杂度：排序为 `O(n log n)`，遍历为 `O(n)`，总复杂度 `O(n log n)`，空间复杂度 `O(n)`。

易错点：边界相等时通常也算重叠，例如 `[1,3]` 和 `[3,5]` 应合并为 `[1,5]`。

### 出现次数最多的数字

> 给定一个整数数组，找出出现次数最多的数字；如果有多个数字并列最多，返回所有这些数字。

解题步骤：

1. 创建 `Map`，键是数字，值是出现次数。
2. 第一次遍历数组：每遇到一个数字，就执行 `map.set(num, (map.get(num) || 0) + 1)`。
3. 遍历 `Map` 的值，找到最大出现次数 `maxCount`。
4. 再遍历 `Map` 的键值对，把次数等于 `maxCount` 的数字放入结果数组。
5. 例如 `[1,2,2,3,3,4]` 的最大次数是 `2`，结果为 `[2,3]`。

复杂度：统计和收集都只遍历一次，时间复杂度 `O(n)`，空间复杂度 `O(k)`，`k` 为不同数字的数量。

易错点：如果题目只要求返回一个数字，可以在统计时维护当前最大值；如果要求处理并列，建议分两次遍历，逻辑更清楚。

### 最长公共前缀

> 给定字符串数组 `["flower","flow","flight"]`，返回所有字符串的最长公共前缀；没有公共前缀时返回空字符串。

解题步骤：

1. 如果数组为空，直接返回 `""`；否则将第一个字符串 `"flower"` 作为当前公共前缀 `prefix`。
2. 从第二个字符串开始逐个比较。例如比较 `"flower"` 和 `"flow"`：
   - 用 `startsWith(prefix)` 判断后一个字符串是否以当前前缀开头。
   - 如果不是，就删除 `prefix` 的最后一个字符，再重新判断。
   - `"flower"` -> `"flowe"` -> `"flow"`，此时匹配，保留 `"flow"`。
3. 继续用 `"flow"` 比较 `"flight"`：
   - `"flight".startsWith("flow")` 为 `false`。
   - 缩短为 `"flo"`，仍不匹配。
   - 缩短为 `"fl"`，`"flight".startsWith("fl")` 为 `true`。
4. 所有字符串比较完成后，返回当前 `prefix`，示例结果为 `"fl"`。

也可以按字符列比较：比较所有字符串的第 `0` 位、第 `1` 位，遇到某一列字符不一致就停止。

复杂度：设字符串总字符数为 `S`，常见实现时间复杂度约为 `O(S)`，空间复杂度为 `O(1)`。

易错点：缩短前缀时必须从末尾删除字符；不能只比较相邻字符串后直接返回，因为后续字符串可能进一步缩短公共前缀。

### 版本号比较

> 给定两个版本号字符串，例如 `"1.01"` 和 `"1.001"`，比较它们的大小，忽略每一段开头的多余零。

解题步骤：

1. 按 `.` 切分两个版本号：`"1.01"` -> `["1","01"]`。
2. 从左到右逐段取值，使用 `Number()` 转成数字，因此 `"01"` 和 `"001"` 都按 `1` 比较。
3. 如果同一位置的数字不同，较大的版本号更大。
4. 如果当前段相同但一方已经结束，缺失部分按 `0` 处理。
5. 例如 `"1.01"` 和 `"1.001"` 比较结果相等；`"1.2"` 与 `"1.10"` 比较时，比较数字 `2` 和 `10`，所以 `"1.10"` 更大。

易错点：不能直接按字符串比较，否则 `"1.10"` 可能被错误判断为小于 `"1.2"`。

### 字符串转驼峰

> 给定由分隔符连接的字符串，例如 `"hello-world-test"`，转换为驼峰格式 `"helloWorldTest"`。

解题步骤：

1. 按 `-`、`_` 或空格切分字符串，例如 `"hello-world-test"` -> `["hello","world","test"]`。
2. 第一段保持原样，作为结果的开头。
3. 从第二段开始，将首字母转成大写，再拼接剩余字符：`world` -> `World`。
4. 最终拼接得到 `"helloWorldTest"`。
5. 需要约定边界行为：连续分隔符是否忽略空段、空字符串返回什么、是否保留首字母大写。

推荐先用正则统一分隔符，再过滤空字符串，避免 `"hello--world"` 产生异常结果。

### Promise.all

> 手写一个 `Promise.all`：接收 Promise 或普通值组成的数组，保持结果顺序；全部成功时 resolve，任一任务失败时 reject。

实现思路：

1. 创建结果数组 `results`、已完成数量 `count`，并记录输入长度 `total`。
2. 遍历输入数组，对每一项使用 `Promise.resolve(item)`，这样普通值也能被统一处理。
3. 每项成功后，将结果写入原索引 `results[index]`，不能使用 `push`，否则异步完成顺序会打乱结果顺序。
4. 每完成一项就让 `count + 1`；当 `count === total` 时统一 `resolve(results)`。
5. 任一项失败时立即 `reject(error)`，后续结果不再影响最终状态。
6. 输入为空数组时，直接返回一个 fulfilled 的 Promise，结果是 `[]`。

复杂度：时间复杂度 `O(n)`，空间复杂度 `O(n)`。

易错点：Promise 的完成顺序和结果顺序不是一回事；必须用输入索引保存结果。
